# ALANET — дорожная карта второго месяца

## Неделя 1 — коммерческий запуск сайта

- Получить реквизиты продавца, проверить оферту, конфиденциальность, согласие и возвраты с юристом.
- Включить публичный checkout и провести по одному test-mode платежу `start`, `calm`, `year`.
- В присутствии владельца карты выполнить один минимальный реальный платеж и финансовую сверку ЮKassa.
- Добавить автоматические чеки и сценарий возврата.

## Неделя 2 — секреты и доступ

- В согласованное окно последовательно сменить Telegram token, ключи ЮKassa, Remnawave API token, DB/Redis secrets и SSH deploy key.
- После каждой ротации выполнить health-check и только затем отозвать старый секрет.
- Перевести релизы на ограниченный CI runner; убрать постоянный Docker/root-эквивалентный доступ у обычного deploy-пользователя.
- Настроить внешнее зашифрованное хранилище backup и еженедельный restore-test.
- Оптимизировать multi-stage web image и runtime-зависимости; увеличить диск либо гарантировать не менее 5 ГБ свободного места перед release build.
- Выполнить контролируемый major upgrade ESLint/Drizzle и добиться чистого dependency audit без `--force`.

## Неделя 3 — тестовый контур и наблюдаемость

- Поднять staging PostgreSQL/Redis и mock-сервисы Remnawave/ЮKassa.
- Автоматизировать матрицу переходов `trial/start/calm/year`, повтор webhook, failed provisioning, expiry и recovery.
- Развернуть Prometheus/Grafana и алерты по SLA, latency, очереди provisioning, диску и сроку TLS.
- Провести согласованный тест отказа одной выделенной ноды без воздействия на общие VPS.

## Неделя 4 — операционная админка

- Реализовать web admin panel с ролями, 2FA через Telegram, аудитом и подтверждениями.
- Добавить поиск клиента, заказы, платежи, ручной retry, возврат и историю подписки.
- Добавить тикеты поддержки, шаблоны ответов и выгрузку финансовой сверки.
- Провести RC, restore/rollback rehearsal и опубликовать отчет второго месяца.

## Метрики месяца

- 100% тарифов имеют автоматический E2E-тест.
- 100% production-секретов заменены и отсутствуют в Git/логах.
- Restore-test выполняется еженедельно, backup хранится вне основной VPS.
- Provisioning success rate не ниже 99.5%, все ошибки создают алерт и повторную задачу.
- Публичный checkout включен только после юридической готовности и реального контрольного платежа.
